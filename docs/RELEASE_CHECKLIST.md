# Контрольный список релиза КВЕРАТО

[← На главную](../README.md)

Этот документ предназначен для подготовки **новых** релизов. Первоначальные архивы 1.0 в каталоге releases/v1.0/ сохраняются без изменений.

## Перед публикацией

1. Выполнить проверки кода, ссылок документации и безопасности Git:

   ~~~powershell
   python tools/release_audit.py
   python tools/core_smoke.py
   python tools/weekly_smoke.py
   python tools/rewards_smoke.py
   python tools/goals_smoke.py
   python tools/economy_regression.py
   python tools/statement_pagination_smoke.py
   python tools/upgrade_from_v1_smoke.py
   python tools/repo_health.py
   python tools/check_docs_links.py
   ~~~

2. Проверить результат GitHub Actions на Linux и Windows.
3. Убедиться, что в будущую сборку не включены .env, реальные SQLite-базы игроков, резервные копии, приватные файлы и локальные виртуальные окружения.
4. Проверить запуск и регистрацию команд на тестовой площадке соответствующей платформы.
5. Проверить денежные операции: повторная ежедневная награда, переводы, покупки и одновременные события.
6. Проверить графические карточки и их резервное отображение при отказах API.
7. Проверить обновление с предыдущей базы **на копии**, а не на рабочих данных пользователей.
8. Проверить Windows BAT-файлы после распаковки (переносы CRLF).
9. Подготовить журнал изменений и контрольные суммы SHA-256 для новых архивов.
10. Только после успешного живого теста объявить версию официальным релизом.

## Правила версионирования

Версию изменяют только при выпуске нового ПО; изменения README и внутренних проверок сами по себе **не создают новый игровой релиз**. Для VK, Telegram и Discord допустимы отдельные номера версий, если изменяется только одна платформа.

## Защита данных

Не храните токены и пользовательские базы в Git. Если токен случайно оказался в публичной истории, его нужно **немедленно перевыпустить** через соответствующую платформу. Удаление строки из нового коммита не делает старый токен секретным.
